# PRD implementation audit — 31 October 2026

## Conclusion and basis

**The PRD is not fully complete.** Version 0.5.0 implements a substantial offline,
controlled-import system, but several requirements remain partial, two functional
regressions were reproduced, and production operation is not activated. Passing
192 tests does not establish full PRD compliance or certification of real inputs.

Reviewed `docs/PRD.md` sections 1–17 against application code, schemas, CLI,
configuration, tests, committed data and current GitHub metadata. Reviewed local
commit `35df12feb504813bb2156a0de9482dd5e2ddab86` and the identical published file tree
at GitHub commit `5db3f2753e0bb88be47672166d2dfabbf094e848`. The latter was imported
through the GitHub connector with new commit IDs; original IDs are retained in its
import messages. This audit does not modify analytical records or fix application
code.

The agreed later constraints matter: controlled imports, deterministic retirement
and no AI service calls are intentional. Live acquisition and Monte Carlo are not
silently added to the remaining implementation scope. R2 is a later requested
integration, rather than a requirement of the original PRD.

## Reproduced results

Reproductions used the synthetic Phase 4 fixture and in-memory functions, without
publishing or altering the accepted workspace.

1. **Dividend continuity:** a bank dividend initially returns `RECEIVED`, eligible
   quantity `100`. Advance to a valid new ledger window, 10–12 October, with the same
   closing positions/cash, no new transactions, and the previously accepted receipt
   still in history. The same dividend returns `PENDING_CONFIRMATION`, quantity
   null. Its evidence remains valid through 12 October. This isolates window
   handling rather than expiration or missing receipts.
2. **Net pending:** the resulting dividend record contains `gross_pending` but no
   `net_pending` field, despite a known tax rate in the fixture.
3. **Catalyst assessment date:** input cutoff 9 October, assessment 10 October,
   catalyst start 20 October. Reported countdown: **11** days; expected: **10**.
4. **Scenario linkage:** change a valuation scenario ID to
   `unlinked-audit-scenario`; Bundle validation accepts it without any macro
   scenario mapping. This demonstrates the absence of an enforced shared link,
   rather than asserting that all domain scenarios must use identical names/IDs.

## Later integration request: Cloudflare R2

**Not implemented.** No R2/S3 client, object manifest, authenticated pull/push CLI or
GitHub workflow transfer steps exist. Environment credential configuration does not
implement these features or prove connectivity. R2 should retain explicit input
validation, immutable run prefixes, content hashes and separate credentials. It is
additional agreed work to specify/implement, not an original-PRD acceptance failure.

The chat request bridge currently supports retirement and cross-asset modules only.
The broader portfolio/valuation/event commands exist in the CLI; invoking those
through equivalent GitHub request files would be a further interface extension.
